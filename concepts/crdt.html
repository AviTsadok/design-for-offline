CRDTs & Collaboration

Send the change, not the whole entity, and don’t lose anyone’s intent.

Conflict-free Replicated Data Types

A CRDT is a data structure that several devices can edit independently and that always converges to the same state once every device has seen every change, with no central coordinator deciding who wins.

The core shift: send the change, not the whole entity.

Whole entity

  • items: ["Apple", "Banana", "Mango"]
  • value: 43
  • text: "Visit Berlin"

Change message

  • Add “Mango” to the list
  • Increase the counter by 1
  • Insert “Berlin” after (space#42)

CRDT messaging rules

  • Message order doesn’t matter. Applying A then B gives the same result as B then A.
  • Duplicate messages don’t affect the final state. Applying a change twice is the same as applying it once (idempotency), so retries are safe.

Every replicated edit, local or remote, goes through the CRDT. The local store is a projection the UI reads from.

Model changes as domain commands that capture intent, not raw field diffs:

// Intent: “Move the meeting to 14:00”
{
  "type": "rescheduleEvent",
  "eventID": "event42",
  "startHour": 14,
  "endHour": 15
}

Because start and end move together, the -1 hour meeting from field-level merging can’t happen.

Even CRDTs aren’t perfect

  • Text interleaving. Characters get fractional positions (0.2, 0.4, 0.6…). If two users type “Universe” and “World” after “Hello” at the same time, the characters can interleave into nonsense such as “Hello UnWoriverseld”.
  • Reordering items. Delete plus insert is not a safe substitute for move: two devices moving the same item can duplicate it. You need a real “move” operation.
  • Trees become graphs. Device A makes Tom Alice’s manager while device B makes Alice Bob’s manager. Each edit is valid alone, but together they can create a cycle.

It’s up to the backend to reject changes and refine the data.

Tools that help

CloudKit, Firebase, Couchbase and Yjs each make different guarantees. Use sync tools with an understanding of what they promise. See the further reading for CRDTs, hybrid logical clocks, operational transformation and idempotent APIs.
